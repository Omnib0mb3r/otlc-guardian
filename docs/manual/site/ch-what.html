What Guardian is

The parts of Guardian, which layer each one defends, where each runs, and the version and release state of 1.5.0.

Guardian is one Node package with no runtime dependencies (package.json: "dependencies": {}, "engines": { "node": ">=22.0.0" }, "type": "module"). It has five kinds of part: documents an agent reads, code that runs inside the project being protected, code that runs inside Claude Code, a check for files that arrive from outside, and a command-line tool that installs and checks the rest.

Rule ids

Two id spaces exist and must not be confused. Audit rules (chapter 02) keep their family ids: SEC-, CFG-, ERR-, INJ-, AUTHZ-, VAL-, WEB-, DEP- and the others listed there. The runtime scanner's patterns (chapter 03) carry a GUARD- prefix since 1.5.0 (GUARD-INJ-001 to GUARD-INJ-028, GUARD-SEC-001 to GUARD-SEC-015, GUARD-INJ-UNICODE, GUARD-INJ-OVERSIZE). Before 1.5.0 both used bare INJ- and SEC-, so INJ-001 named two different checks. For 1.5.0 only, each runtime violation also carries its old id as legacyId (Python: legacy_id); 1.6.0 removes it. The mapping table is in CHANGELOG.md, 1.5.0, "Changed".
